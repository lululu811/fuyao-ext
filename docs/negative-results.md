# 负面实验记录：试过什么，为什么扔掉

<!-- 本章内容对应 indicators_config.yaml 头部注释（2026-09-30 评估批次）。 -->

开源项目通常只记录「我做成了什么」。这一章记录**做不成什么** ——
在第二批 30 个候选指标中，有 7 个（23%）被实测否决，以及否决的理由。

保留这些记录的理由很简单：**下次有人（包括我自己）会想再试一遍它们。**
没有这份记录，这些调研会重做一遍。

---

## 批次概况

- **候选数**：30
- **否决**：7（23%）
- **共同特征**：**全部表现为「能算、不报错、值域离谱」**

最后这一点是本章最要紧的经验：这些指标**不会以异常的形式暴露问题**。
它们安静地返回一个数字，插进宽表，没人发现，直到有人手工复算。

---

## 被否决的指标

| 指标 | 名称 | 否决理由 |
|---|---|---|
| SAREXT | 扩展抛物线 | 实测本 build 的 `talib.SAREXT` **输出会发散**：在 600519.SH（价格区间 1151~1772）上 50%+ 取值为负、末值 −1301。对 `startValue` 取 0.02 / 0 / 首收盘价 三种变体结果一致，说明不是参数语义问题。同题的 `talib.SAR` 末值 1277、零负值正常。相对 PSAR 的增量只是「多空两侧用不同加速上限」，不值得冒往宽表写脏数据的风险。 |
| KST | 库普考克 | 实测值域比标准定义**大 100 倍**：茅台手工复算 [−96.8, 138.0] vs 库 [−9684.7, 13804.4]，重叠段最大绝对差 13666。同一指标在不同价位个股上的「KST / 价格量级」从 10x 跳到 1951x，不是干净的缩放误差。 |
| EFI | 效率因子 | 库输出 ±5.45e8，按定义 `(C−C_prev)/V×10000` 手算只有 ±0.13，**差约 4e9**。 |
| CG | 钱得 Kroll 通道 | 值域 [−5.63, −5.15]，666 根里 657 个不同值，而同期价格在 1237~1259 波动 —— **通道与价格完全无关**。 |
| RVGI | 相对成交量指数 | 与定义式手工复算**偏差 89.9%**，且无法确认本 fork 使用的确切归一化方式。无法验证就不进表。 |
| MAVP | 变周期均线 | 不是质量问题，是表达能力问题：TA-Lib 的 `periods` 是**逐 bar 数组**而非标量，现有 `params: [...]` 表达不了。需要先定一条周期生成规则 —— 那是策略参数决策，不该由实现者顺手决定。 |
| VP | 成交量分布 | `ta.vp(close, volume)` 返回的是 **10 档分布快照 DataFrame**，不是逐日序列，无法像其它指标一样摊平成宽表的列。真要加，得先定义「取哪几个字段、怎么聚合成日频」。 |

注意后两条的性质不同：MAVP 和 VP **没有测出质量问题**，是被数据模型的表达能力挡住的。
把它们和前五条并列，是为了说明「否决」有两种原因 ——
一类是**实测是坏的**，一类是**当前 schema 装不下**。后者是可复活的，前者不是。

---

## 沉淀下来的教训

> 第二批 30 个候选里有 7 个（23%）是坏的，而且全都表现为「能算、不报错、值域离谱」。
> 所以任何新指标进表前都要**手工复算一遍定义**，不能只看函数存在。

这条规则已经固化进了工程：`scripts/add_indicators.py` 带
`scan_null_columns()` 扫结构性 NULL 列，配置层有 `enabled` 开关，
列数由 `expand_columns()` 推导而非写死。

但要说清楚：**上面 7 个里，只有 NULL 扫描能自动拦住一部分。**
值域离谱的那几个（KST、EFI、CG、RVGI、SAREXT）**任何自动化检查都拦不住** ——
它们返回的确实是合法数字。只是目前**还没有把「值域合理性」做成自动闸门**，
这一步仍依赖人工复算。把它自动化（例如按 `(因子, 价格量级)` 检查量级一致性）
是一个明确的待办。

---

## 怎么复算

手工复算的做法是拿同一天同一只票，分别用**指标库的定义式**和**库的实现**
各算一遍，然后比对：

1. 从定义式独立写一遍计算（不看库的实现）
2. 同一只票、同一天，比对两组数值
3. 差一个数量级以上 → 直接否决，不查原因
4. 差几个百分点 → 查归一化口径，确认后记录

KST 和 CG 就是在第 3 步被拦下的。RVGI 在第 4 步卡住 —— 偏差 89.9%，
但因为无法确认 fork 的确切归一化方式，也就无法确认谁是错的，于是放弃。
