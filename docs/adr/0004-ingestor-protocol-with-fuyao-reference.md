# 采集层用 Ingestor 抽象，附一个上游参考实现

---
status: accepted
date: 2026-10-02
---

采集层定义为 `Ingestor` 抽象：只认本项目的数据契约，不认数据源。本项目附带**一个**针对上游数据服务自行编写的参考实现。

上游服务已公开发布客户端 CLI（`@hithink-tech/hithink-finance-cli`），且其产品定位明确面向 AI Agent 与开发者。**自行编写客户端调用其公开 API 属于其商业模式的一部分**；这与 [ADR-0002](./0002-exclude-hithink-financial-api.md) 中"不再分发其仓库代码"并不矛盾，但两者之间的界线必须划清楚：

- **可以**：按公开 API 文档自行实现调用、字段映射、错误处理与重试
- **不可以**：复制、改写或再分发其仓库中的实现代码

## Considered Options

- **只针对上游服务实现，不做抽象** —— 工作量最小，但项目会退化为"上游客户端的周边工具"，使用者被绑定在单一数据源上。
- **只定义抽象，不附任何实现** —— 边界最干净，但使用者拿到的是空壳。鉴于 [ADR-0001](./0001-distribute-schema-not-data.md) 已经把"自己准备数据"设为主要门槛，不应再叠加第二道门槛。
- **抽象 + 一个参考实现** —— 采纳。抽象层成本很低，且能让 README 站得住一句话：任何能提供证券标识、日线 OHLCV 与复权因子的数据源都能接入。

## Consequences

- 抽象层需明确定义"最小输入数据集"：证券标识、日线开高低收、成交量额、复权因子。在此之上（财报、指数、基金、期货、特色数据）属于可选能力，不进核心契约。
- 项目命名沿用 `fuyao-ext`，因此**必须在 README 显著位置声明上游数据服务为同花顺 hithink-finance（`fuyao.aicubes.cn`）**，并说明：本项目不提供数据、不保证上游可用性、参考实现可被任意其他数据源替换。
- 项目名含上游商标，属于刻意选择而非疏忽 —— 它准确地描述了本项目"上游的一个扩展工具"这一定位。README 的署名段落必须与之一致。
- 未来接入第二个数据源（tushare / akshare / 自建）时，抽象层是否足够通用会被真正验证。现在只有一个实现，抽象是否恰当**尚未被证明**，这一点应在 README 中如实说明。
