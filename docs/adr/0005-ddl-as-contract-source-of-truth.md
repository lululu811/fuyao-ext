# 数据契约以可执行 DDL 为唯一事实源

---
status: accepted
date: 2026-10-02
---

本项目的数据模型以**可执行 DDL**（`schema/*.sql`）作为唯一事实源。ER 图、字段字典、表清单、README 中的模型说明等一切文档产物，**均从 DDL 生成**，不手工维护。

## 理由

现有实现已经证明手工文档必然失真：`indicators` 表的列数由配置推导、随指标增减而变化，早期文档中的列数快照已经与实际不符，代码注释中因此明确写着"不要相信文档里的快照"。指标引擎已有的建表代码是从配置生成 DDL 的，这条路已经走通，只需扩到全部数据域。

选择 DDL 而非 PowerDesigner `.pdm` 或 DBML 的具体原因：

- **可执行**：任何人一条命令即可建出全部表与视图，看到的就是真正能跑的东西
- **可 diff**：模型变更在 code review 中可见，`.pdm` 的 XML 不可读
- **可校验**：CI 中反复建表即可发现模型损坏

## Consequences

- 贡献者改表的正确路径是改 DDL（及生成它的配置），而不是改文档。反过来若有人手工编辑生成的文档，CI 必须能发现。
- 需要投入一个生成器（表清单、ER 图、字段字典），并把它接进 CI。这是本项目为数不多"为了文档而写代码"的地方。
- 需保留一份**模型自检**：当前已建库的 7 个 DuckDB 中 **一个主键约束都没有**（建表语句里声明了，但数据是绕开约束批量写入的），因此"DDL 与现存库是否一致"无法靠约束保证，必须由自检脚本比对。
